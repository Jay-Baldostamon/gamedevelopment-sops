# engineering-sops

Version-controlled documentation for the Engineering Department.

This repository is the home for the department's operating knowledge, not just standard operating protocols. It replaces scattered Google Docs with a single GitHub source of truth so documentation can be versioned, reviewed, searched, and reused with AI-assisted workflows.

## What belongs here

Use this repo for any Engineering Department documentation that should be kept current and discoverable, including:

- standard operating procedures and playbooks,
- architecture and technical standards,
- incident response and risk documentation,
- career ladder and role expectations,
- review notes, prompts, schemas, and reusable templates,
- other internal documentation that needs durable version control.

## Repository Layout

- `docs/architecture/` - system architecture standards and design references
- `docs/career-ladder/` - role expectations and promotion criteria
- `docs/incident-response/` - incident assessments, risk acceptance, and response records
- `docs/playbooks/` - department and workflow playbooks
- `docs/value-engines/` - operational frameworks that describe how engineering work creates value
- `templates/` - reusable document and SOP templates
- `schemas/` - structured document or data schemas
- `reviews/` - review artifacts and evaluation notes
- `prompts/` - prompt libraries and AI workflow support material

## Why GitHub Instead of Google Docs

- Clear version history and change tracking
- Pull request review before publishing changes
- Easier collaboration across the department
- Better searchability and reuse
- Stronger support for AI-assisted drafting, review, and maintenance

## Working In This Repository

- Keep documents in Markdown unless a different format is clearly required.
- Prefer small, focused updates over large unreviewed rewrites.
- Treat important documentation like code: make changes through branches and pull requests when applicable.
- Keep content current, concise, and easy to scan.

## Suggested Contribution Flow

1. Find the most relevant document or folder.
2. Update the content in a focused commit or pull request.
3. Review the change for accuracy, clarity, and consistency.
4. Link related documents when a topic spans multiple areas.

## Maintenance

If a document becomes stale, duplicate, or difficult to find, update this repository rather than creating a new Google Doc.
