Week 1 builds the foundational L1→L2 skill: turning a product brief into a complete technical breakdown without being handed a ticketed task list. This is the exact shift the promotion gate measures.

## What to Expect This Week

The Decomposition Format (applies to every feature this program):

1. Required schema changes (Prisma models, relations, indexes, constraints; migration path)
2. API route design (endpoints, methods, zod validation boundaries)
3. Component tree (what renders, state ownership)
4. State-management approach (which state, where it lives, how it updates)
5. Test plan (unit + integration + boundary cases)

- **Day 1:** Read the promotion gate document (`docs/career-ladder/backend/L1 to L2 Promotion Gate.md`), especially G1. Learn the Decomposition Format.
- **Day 2:** Guided decomposition #1 — walk through a past shipped feature with a Senior and reproduce its breakdown.
- **Day 3:** Guided decomposition #2 — decompose a moderate product brief (e.g. "build a user notification preferences page") with a Senior, who corrects each section.
- **Day 4:** Independent decomposition #1 — pick a fresh brief and complete all five sections without step-by-step guidance; submit to the Senior reviewer.
- **Day 5:** Reviewer feedback + rework day. Revise against feedback; log estimation accuracy for the estimate you gave.

## Week 1 Success Criteria

- [ ] Can author the Decomposition Format from memory (all five sections)
- [ ] Completed 2 guided decompositions
- [ ] Completed 1 independent decomposition and submitted for Senior review (G1 evidence, decomposition #1)
- [ ] Incorporated reviewer feedback into a revised decomposition

## Guiding Principle

Decomposition is the difference between L1 (given a ticket) and L2 (given a brief). The five-part format is non-negotiable from Week 1 onward.
