## Unity Game-Development Track Context

This level or week uses the same desktop 2D C# action-platformer on the current Unity LTS release. The Unity gameplay lane covers scripts, scenes, prefabs, assets, tests, and builds. The former DB lane is now the game data lane for player profiles, save slots, checkpoints, collectibles, unlocks, and leaderboard contracts.

For L3/L4, scheduling, agents, and cloud workers support the Unity repository and build/test pipeline. Use only approved mock or game-specific data, not CRM or unrelated production systems. If a fixture is unavailable, identify the blocker locally and keep the work design-only. Preserve authorization, independent review for actual PRs, and secret-handling controls; no training reports or supervisor sign-offs are required.

## What to Expect This Month

- Week 1: Shared Core (Days 1-3) plus lane onboarding on debugging/code literacy (Days 4-5)
- Week 2: Lane execution fundamentals (Unity Gameplay Lane or Game Data Lane) with role-aligned scope control and recovery
- Week 3: Lane ownership workflow with reconverged Day 14 task creation and lane-specific Day 15 execution
- Week 4: Lane reinforcement (Days 16-18) then reconverged Day 19 translation and Day 20 retrospective

## Month 1 Success Criteria

- [ ] Shared Core (Days 1-3) is completed before lane execution begins
- [ ] Unity Gameplay Lane or Game Data Lane is explicitly selected and followed for execution days
- [ ] Week 1 code literacy is practiced and checked locally
- [ ] Week 2 version-control recovery is practiced locally
- [ ] Week 3 issue-to-PR and review workflows are completed end-to-end
- [ ] Week 4 ends with local reflection on the playable slice and the next improvement

## Local Quality Checks

- Check code understanding and recovery against the actual project or an approved mock fixture.
- Mark unavailable tests and tooling as blocked rather than claiming success.
- Preserve authorization, required CI, and independent human review when a real project PR is used.

## Guiding Principle

The month is successful when execution quality, traceability, and repeatability are demonstrated consistently across all four weeks.
