Day 3 turns an idea into a one-page pitch, breaks it into buildable steps and proves the core loop in a browser prototype. It is the day the game is chosen: the pitch made today is the same game through Day 20, and the **Pitch** milestone is scored today.

**Gate:** milestone gate. Score the pitch against [Rubrics](../../Resources/Rubrics.md) → Day 3 before moving to Day 4.

The authoritative lesson is [Day 3 of the Tools-Only 80-Day Learning Plan](../../Tools-Only%2080-Day%20Learning%20Plan.md#day-3--decomposition-your-game-pitch); this blueprint is its expanded execution form.

### Session: Preparation

#### Prerequisites

Before starting, confirm you have:

* Day 2 complete, with the three prompting rules written in your own words
* Google AI Studio Apps access for the core-loop prototype
* A timer for the four-hour idea limit
* [Rubrics](../../Resources/Rubrics.md) open at Day 3
* A recorder for the walkthrough, and a `Day 3` evidence folder

#### Scope Rules for the Rest of L1

A full playthrough takes 10 minutes or less; one level or arena; Windows PC, keyboard and mouse. Not allowed: multiplayer, mobile, open world, save systems, extra game modes. The game must be fun with plain shapes.

#### Daily Evidence Standard

* Today's evidence lives in the `Day 3` folder. The game repository does not exist yet.
* The pitch, the build steps and the initial prompt are separate files in that folder.
* The prototype GIF and the walkthrough link are recorded there too.
* The rubric is scored from the evidence, without asking you anything extra.
* No standup post and no supervisor sign-off are required on this path.

### Session: Core Execution

#### Step-by-Step Checklist

### Phase 1: Choose the idea (timeboxed)

1. Choose your idea inside a four-hour limit. If you reach four hours, take the smallest idea on your list.
2. Check the idea against the scope rules before writing anything.

### Phase 2: Write the one-page pitch

1. Fill every heading: one line; player action (one verb); core loop (three steps or fewer); win; lose; why it is fun; 10-minute scope; not in this game (three things); view (2D top-down, 2D side-on, 3D third-person, 3D first-person).
2. Break only the core loop into four to eight numbered build steps.

### Phase 3: Prototype the core loop

1. Write the initial prompt using your Day 2 rules.
2. Build the core loop in AI Studio with plain shapes. Stop when you can answer: "Is the core loop fun for 60 seconds?"
3. If it is not fun, change the pitch now. After today the game is locked for Day 20.
4. Record a walkthrough of 15 minutes or less: read the pitch, play the prototype, say what works and what does not.

### Phase 4: Scope check

1. Ask someone to read the pitch once and explain the core loop back to you. If they cannot, rewrite the pitch.

### Session: Quality and Reflection

#### Common Mistakes & Fixes

| **Mistake** | **Fix** |
| --- | --- |
| Choosing an idea that needs great art to be fun | Pick an idea that works with plain shapes only |
| Writing a pitch longer than one page | Keep one line per heading and stop |
| A core loop with five or more steps | Cut it to three steps or fewer before prototyping |
| Starting the prototype before the pitch is finished | Finish and read the pitch first; the prompt comes from it |
| Keeping an idea that is not fun after 60 seconds | Change the pitch now, while the game is still unlocked |
| Skipping the reader check | Have someone read it once and repeat the loop back |
| Spending the day polishing the browser prototype | Stop at "is the loop fun?"; Unity starts on Day 4 |

#### Standards & Governance

* The pitch is the contract for Days 4–20; changing the game later costs the whole week.
* The 10-minute playthrough, one arena, and the five exclusions are pass conditions, not preferences.
* The prototype exists only to answer one question: is the core loop fun for 60 seconds?
* Gate scoring uses [Rubrics](../../Resources/Rubrics.md) → Day 3; every line must be Yes.

## Implementation Examples (if needed)

The pitch headings, filled in for a plain-shape game, are the model to copy:

```text
One line:       A one-screen arena where you dodge falling crates and catch coins.
Player action:  Dodge.
Core loop:      Read the falling pattern, move, collect or avoid.
Win:            30 coins in 90 seconds.
Lose:           Three hits.
Why it is fun:  The pattern speeds up, so the same move gets harder to time.
10-minute scope: One arena, 90-second rounds, restart from the same screen.
Not in this game: Enemies that shoot, upgrade menus, multiple levels.
View:           2D top-down.
```

## End-of-Day Checklist

- [ ] The pitch fits on one page and every heading is filled.
- [ ] It names one player action, a core loop of three steps or fewer, and how I win and lose.
- [ ] A playthrough would take 10 minutes or less in one level or arena.
- [ ] It uses none of: multiplayer, mobile, open world, save systems, extra game modes.
- [ ] The core loop is playable in a plain-shape browser prototype and is fun for 60 seconds.
- [ ] After one read, someone else explains the core loop back correctly.
- [ ] The game is locked for the rest of L1.
