Day 1 is the exposure day: it builds comfort with AI conversation using games as the subject and starts the evidence habit every later day depends on. Nothing is built today. The output is five Gemini threads, ten screenshots and five gap notes.

The authoritative lesson is [Day 1 of the Tools-Only 80-Day Learning Plan](../../Tools-Only%2080-Day%20Learning%20Plan.md#day-1--exposure-game-ideas); this blueprint is its expanded execution form.

### Session: Preparation

#### Prerequisites

Before starting, confirm you have:

* Company email access, with [Gemini](https://gemini.google.com/app) opening under it
* Level 1 pre-flight complete: the pinned Unity LTS version with **Windows Build Support**, VS Code with the Unity extension and the AI assistant signed in, Git, Git LFS and GitHub Desktop installed, a screen recorder, and at least 40 GB free disk
* A workspace folder for today's evidence, outside Google Drive, OneDrive and Dropbox

#### Daily Evidence Standard

* Today's evidence lives in a `Day 1` folder inside the workspace. The game repository does not exist yet.
* Text outputs: save each one as a Markdown or plain-text file in that folder.
* Screenshots: save them as image files in the same folder.
* Videos or GIFs: upload to a shareable location and paste the link into a note in that folder.
* AI agreement is not evidence. Only saved artefacts you can point to count.
* No standup post and no supervisor sign-off are required on this path.

### Session: Core Execution

#### Step-by-Step Checklist

### Phase 1: Set up

1. Log in to [Gemini](https://gemini.google.com/app) with your company email.
2. Create a `Day 1` folder in your workspace for today's evidence.

### Phase 2: Run five threads

1. Create five separate chats, one topic each:
   * **A game you love.** Ask why it is fun, push back on the answer, and ask what the one core thing the player does is.
   * **Mechanics.** Ask for 10 simple mechanics, pick one, then ask how it could be twisted into something new.
   * **Small games.** Ask what makes a game finishable in 10 minutes still feel complete.
   * **Game feel.** Ask what "juice" or game feel means and how a plain game becomes satisfying.
   * **Your ideas.** Give three rough game ideas and ask which is smallest to build and why.
2. Send at least five prompts in each chat.
3. Push back at least once per thread: "why?", "what is the downside?", "give me a smaller version".
4. Do not pick your Day 3 game today. Day 1 is exposure, not selection.

### Phase 3: Capture evidence

1. For each thread, screenshot your first prompt and the final answer.
2. Write one line per thread: what the answer gave you and what it missed.

### Phase 4: Keep moving when blocked

1. State the topic, what you finished, and ask for the next step: "Today I am learning to work with AI so I can build a Unity game. I have finished five chats about game ideas and mechanics. What should I practise next?"

### Session: Quality and Reflection

#### Common Mistakes & Fixes

| **Mistake** | **Fix** |
| --- | --- |
| Treating Day 1 as game selection | Keep it exposure only; the game is chosen on Day 3 |
| Sending one long question instead of holding a conversation | Send five prompts and at least one push-back per thread |
| Accepting the first answer | Push back once per thread: "why?", "what is the downside?", "give me a smaller version" |
| Screenshotting only the final answer | Capture the first prompt and the final answer for every thread |
| Writing a summary of what the AI said | Write what it gave you and what it missed |
| Leaving the evidence in the chat window | Save every screenshot and note in the `Day 1` folder |

#### Standards & Governance

* Exposure and volume come before prompt quality today; there is no polish bar beyond saved evidence.
* Every thread has the same shape: five prompts, at least one push-back, two screenshots and one gap note.
* The game stays undecided until Day 3, and nothing is scored today; the Day 3 pitch is the first gate.
* Evidence is recorded, not remembered: a reviewer must be able to read the folder without asking you anything.

## Implementation Examples (if needed)

A gap note has two lines, one for what the answer gave and one for what it missed:

```text
Thread 3 - Small games
Gave me: a ten-minute game feels finished when it has a clear end state, one rising pressure and a score to beat.
Missed: no example of a game with no score at all, and no answer on how long a small game takes to build.
```
