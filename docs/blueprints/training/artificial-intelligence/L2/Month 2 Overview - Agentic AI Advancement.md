Month 2 advances L2 engineers from local AI use into controlled agentic review, development-handoff, and issue-to-PR delivery workflows. Each lesson provides an objective and a copyable prompt for the existing local AI; no daily training issue or submission is required.

## What to Expect This Month

- Focus 1: Set up Hermes locally and confirm least-privilege GitHub access for review, issues, comments, pull requests, labels, and connected Project status.
- Focus 2: Install and practice the review skills in interactive, inform-only, and gap-resolve modes.
- Focus 3: Transform completed issues into evidence-based AI development handoffs in interactive, echo, and auto-post modes.
- Focus 4: Deliver validated handoffs through an issue-linked branch and PR, review request, and `For Review` Project status update.
- Focus 5: Progress from interactive delivery to automated delivery, AI review recommendation, and automated AI review without merging or bypassing CI.
- Focus 6: Culminate the workflow with a local preflight, dry run, scoped Unity implementation, and review practice.
- Throughout: Keep scope explicit, preserve secrets, inspect AI-generated work, retain real validation evidence, and keep human review and CI as merge gates.

## Month 2 Success Criteria

- [ ] Engineer has a working local Hermes installation and can launch the UI.
- [ ] Engineer confirms or requests the least-privilege access needed for review, handoff comments, PR delivery, labels, review requests, and connected Project status updates.
- [ ] The required internal review, handoff, and issue-to-PR skills are installed and loadable in fresh Hermes sessions.
- [ ] Engineer completes interactive and automated reviews without violating repository routing or mutation boundaries.
- [ ] Engineer creates issue development handoffs without rewriting issues or inventing requirements.
- [ ] Engineer completes a plan-only IDE dry run from a posted handoff.
- [ ] Engineer delivers a valid handoff through a scoped implementation, validation, linked PR, review request, and verified `For Review` status—or reports the exact blocker.
- [ ] Engineer runs or recommends the appropriate AI review workflow for a delivered PR without self-approval or merge.
- [ ] Engineer completes the culminating local validation and follows independent review rules if a real PR is used.
- [ ] Agent-generated work remains bounded to the assigned repository and task; human review and CI remain mandatory before merge.

## Month 2 Quality Gate Standard

- Blocking:
  - Hermes launches locally and all required skills load in fresh sessions.
  - Access blockers are explicit and least-privilege; secrets are never exposed.
  - Review, handoff, and delivery outputs are grounded in issue requirements, acceptance criteria, repository evidence, and real validation.
  - Interactive modes require approval at each defined checkpoint.
  - Inform-only modes produce no unauthorized mutation.
  - Gap-resolve and delivery modes change only verified scope, report real validation, and do not claim blocked checks passed.
  - Delivery PRs use a verified issue link, request review, and set `For Review` only after the PR exists.
  - No workflow merges, self-approves, bypasses CI, or rewrites issue bodies.
- Non-blocking:
  - Optional Hermes UI customization and exploration beyond required workflows.

## Month 2 Operating Metrics

- Scope-drift incidence in agent-run work

## Guiding Principle

Month 2 is successful when engineers can progress from authoritative issue to handoff to reviewed pull request with the right level of autonomy, verified evidence, and non-bypassable human and CI controls.
